# Выбор глубины обновления

В начале каждого нового update спроси, если пользователь уже не выбрал режим явно:

«Как обновляем: Full update — заново deep scan, skills и RAG с очисткой старой рабочей истории; или бережный update — только критичные проблемы и необходимые обновления без сноса? Full займёт больше времени и токенов. MCP-серверы и настройки доступа сохраняются в обоих вариантах».

Не трактуй слово «обнови» как разрешение Full. Явный выбор в запросе или `--mode full|incremental` заменяет повторный вопрос. Режим относится к конкретному запуску, не к месту хранения. Сохранённый Git/local storage не переключай и не спрашивай заново без причины.

## Бережный — incremental

Прочитай `incremental-update.md`. Найди критичные ошибки, несовместимые/устаревшие форматы и существенные изменения применимых стандартов. Меняй только необходимое. Не удаляй skills, базы или историю, не запускай full research и не переписывай проектные материалы ради косметики. Неприменимые новые версии и исправные skills оставь. Изменение зависимостей самого продукта не входит в update toolkit.

## Полный — full

Прочитай `full-update.md`. Новые skills и знания собираются заново по fresh deep scan всего согласованного проекта/workspace. Старые skills/RAG и большая часть рабочей истории уходят из активной системы. Основная идея проекта и важные ограничения сохраняются в коротком `project-intent.md`. MCP-серверы, credentials, окружение, Git/CI и storage configuration не сбрасываются. Backup существует только для отката, не как актуальная RAG.

Full — это замена результата, а не требование уничтожить рабочую систему до успешного исследования. Сначала проверенная резервная копия и новая сборка, затем контролируемая активация. Ошибка/недоступный compiler не разрешают удалить старое.

## Команды

```bash
node reusable-agent-system-toolkit/scripts/bootstrap.js update . --check
node reusable-agent-system-toolkit/scripts/bootstrap.js update . --mode incremental --check
node reusable-agent-system-toolkit/scripts/bootstrap.js update . --mode full --check
```

Без `--mode` preflight возвращает `needs-update-mode`; агент задаёт вопрос. Затем проверяется отдельное Git/local хранилище. В full после подтверждения storage доступен read-only план `rebuild / retire / preserve / review`. Ни одна команда выше не удаляет файлы, не запускает LLM/deep scan и не переключает поколение. Deep scan и применение выполняет агент по выбранной инструкции; автоматического `--apply` пока нет.
